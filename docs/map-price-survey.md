# Annual detailed-map interest survey

Status: banner, survey and response storage activated in production on 16 September 2026. A delayed contextual prompt is implemented locally for testing and is not deployed.

## Offer and placement

Test stated willingness to pay for species-map sectors of 250 m and the existing 14-day sector forecast. Ask for the highest considered annual price among **€2.99, €4.99 and €9.99**. A compact banner below the site header presents the benefits without a price and links to `/enquesta-mapa`. It appears across public pages, including the map, but not private/authentication routes or the survey page itself. Closing it snoozes both invitations for 24 hours across tabs; it returns on a later visit if no answer was confirmed. A confirmed answer keeps both hidden across tabs and browser restarts using an optional local receipt hint. The map's existing contribution invitation does not contain a survey.

The local delayed-prompt test uses the same public-route, 24-hour snooze and answer-suppression rules. Its 30-second timer begins only after the first pointer, wheel or keyboard interaction and advances only while the tab is visible. It appears at most once per tab session, offers a clear “Ara no” action that starts the snooze, does not show a price and links to the same survey page.

The dedicated page uses the shared page shell and standard headers. It leads with the offer and immediately visible survey, with equally weighted response options. Short screenshot-led benefit sections and a brief explanation of Aleix’s personal project and server costs follow; secondary resolution and forecast details are collapsed. A same-camera screenshot comparison explains the public 2.5 km smoothed view and exact 250 m sectors. The forecast section describes the existing up-to-14-day sector chart, available with detailed-map access when forecast data is available (`includeOutlook` in the history API). The public map timeline remains +5 days with a 5 km minimum grid; sector resolution is not the resolution of the underlying weather. The subscription is proposed, not the forecast feature. The page is public and directly shareable, but marked noindex and omitted from the sitemap because it is a temporary research page. The banner's measured height is subtracted from the full-page map frame; dismissal restores the space, and fullscreen remains independent.

Participation is optional, has no checkout, creates no subscription and grants no access. The public 2.5 km floor and all contribution rewards remain unchanged. The combined prediction map still stops at 1 km; the offer describes maps for individual species. Finer sectors do not promise better prediction accuracy or guaranteed mushrooms.

The five answers are €2.99/year, €4.99/year, €9.99/year, prefer contributing, and not interested. The question explicitly asks for the highest offered price the respondent would consider. Responses are single-choice with no free text, contact details or account requirement. No price is preselected or highlighted as recommended.

## Response storage and duplicate protection

Version **map-price-v8** keeps the same price question and introduces database receipts. Versions 1–7 were local analytics-only iterations; do not import browser selections or Umami events as verified database responses. The migration is `20260916075324_map_price_survey_responses.sql` and was applied with the production activation on 16 September 2026.

`GET /api/map-price-survey` establishes a signed, HttpOnly, SameSite=Strict first-party cookie with a one-year lifetime. It is scoped to that API path and Secure in production. The signing secret uses the existing `ABUSE_RATE_LIMIT_SECRET`, falling back to the server service-role key; keep it stable during the experiment. The browser identifier is random, independent of accounts and analytics. The database stores only its SHA-256 hash scoped to the survey, the version, allowlisted answer, generated receipt ID and timestamp. It stores no email, account, IP, referrer, map state or fingerprint.

`POST` requires the cookie, a same-origin JSON request and a valid version/answer. A database primary key on `(survey_version, respondent_hash)` permits one immutable response. The first accepted answer wins; double-clicks, concurrent POSTs and retries return that same answer. Web Locks serialize initial cookie setup across tabs where supported. The form rechecks the server receipt before submitting and only acknowledges a confirmed save. A lost response can be recovered by retrying or reloading; failures remain visible and retryable. Blocked cookies cannot produce repeated cookie-less submissions. Browser storage is only a UI hint, never evidence that an answer was saved.

This limits repeat participation per cookie, not per person. Clearing cookies, using another browser/device or cookie expiry can allow another answer. Browsers without Web Locks may also race during simultaneous first-ever cookie initialization. Requiring authentication would be needed for account-level deduplication; even that does not prove one human per account. Existing database-backed abuse limits restrict identity creation (60 per 10 minutes) and new submissions (30 per 10 minutes) per keyed IP hash, separately from responses. Shared networks can encounter those limits. No fingerprinting is used.

The table has RLS enabled, no grants to PUBLIC/anon/authenticated, and only SELECT/INSERT for the server role. The API returns only the current browser's answer and sends private/no-store headers. `/admin/enquesta` requires the existing administrator role at both page and data-reader boundaries. It shows exact per-option counts and percentages plus all individual receipts in pages of 50, without exposing browser hashes. A query failure is an error, not a misleading zero.

Do Not Track, disabled/missing analytics and blocked Umami do not prevent a user-requested response from being saved. Answers are no longer sent to Umami. The privacy notice and form explain storage and the duplicate-prevention cookie. The survey creates no subscription or access grant.

## Optional acquisition analytics

Umami receives only allowlisted acquisition events on the neutral `/analytics-event` path without payload. The banner uses `map-price-v8-shown`, `map-price-v8-clicked` and `map-price-v8-banner-snoozed`; the delayed prompt uses `map-price-v8-prompt-shown`, `map-price-v8-prompt-clicked` and `map-price-v8-prompt-dismissed`; the question uses `map-price-v8-opened`. Each is deduplicated per tab session and respects existing analytics opt-outs. A direct arrival never invents a banner or prompt impression. Banner impressions and question openings require at least half the element to be visible in a foreground tab, or an explicit relevant action. The prompt event is recorded only when its dialog opens after the visible-use delay.

Use `/admin/enquesta` as the source of truth for responses, including participants invisible to analytics. Use Umami separately to understand banner exposure and clicks. Do not divide all database responses by analytics-only visitors/openings: those populations differ. Review after two complete weeks from verified activation, extending if counts are sparse, and report absolute counts alongside percentages. This is a voluntary stated-price preference survey, not a randomized pricing experiment or a revenue forecast. Offered prices can anchor answers; €9.99 selections do not establish an upper willingness-to-pay limit.

To end the experiment, remove the banner and disable writes in the endpoint as well as replacing the form with a closed message. Retain receipts for analysis. No automatic reminder or publishing action is configured.
